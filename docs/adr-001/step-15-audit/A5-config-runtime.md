# A5: Configuration, startup, CLI, cluster, storage, cache and security (v2.56.0 → 0855cd70f)

This audit compares BASE = `v2.56.0` with HEAD = `2-dev` at `0855cd70f`. Paths are relative to each worktree. `HEAD x:n` points at `$S/head/x`, and `BASE x:n` at `$S/base/x`. The storage slice (S-ids) and the security/cache/vault/dump/events slice (X-ids) were audited by two sub-agents and are merged in here under C-ids, with their original ids given in brackets. I re-verified S-01, X-01 and X-02 by reading the code.

## Summary: top risks first

1. **C-01 [S-01]: a missing document no longer returns `services.storage.not_found`. HIGH, breaking, not intended.** The `formatESError` rewrite in both ES wrappers spreads the ES client error (`{...esError, meta}`). The spread drops `body`, which is a prototype getter on `ResponseError`, so `_handleNotFoundError` never sees `body._index`. The result is that `document:get`, `document:delete` and `document:deleteFields` on a missing document return `services.storage.unexpected_not_found` (code 34) instead of `not_found` (code 11), with a different message. The HTTP status is still 404. The unit fixtures set `body` as an own property, which hides the problem, and no functional test pins the error id.
2. **C-02: a cluster node that evicts itself now exits with code 1. Previously it stayed up as a zombie.** This is intended (TD-67, #2785). But `evictSelf` has more triggers than a lost message: any exception thrown by a sync-message handler (for example a plugin's cluster-wide event listener that throws synchronously), an ID-card renewer failure, or a failed Redis connection in the worker. On BASE all of these only logged a line and broadcast the eviction. On HEAD they take the whole node down. Operators will see restarts where they used to see a silent degradation.
3. **C-03: possible join failure introduced by `waitForSubscription` in `addNode()`. Unverified timing risk, not recorded in the ADR.** An existing node now waits up to `2 × cluster.heartbeat` (4 s by default) for a sync message from the joining node before it answers the handshake. The joining node gives up on the handshake after a hard-coded 2000 ms (`command.ts:531`). The joining node only publishes heartbeats, every `cluster.heartbeat` ms, so the reply comes after roughly "time to the joiner's next heartbeat". That usually fits inside 2 s at the default 2000 ms heartbeat, occasionally does not, and very often does not if an operator raised `cluster.heartbeat` above 2000. When it fails, the joiner drops the peer while the peer has added the joiner, leaving an asymmetric membership.
4. **C-04 [X-02]: handled-error dumps can crash in development or be lost silently.** The dump suffix is now validated against `^[A-Za-z0-9_-]{0,64}$`. The funnel's own `handled-<type>-<message>` suffix has no length cap, so a typical `TypeError` message goes over 64 characters. The resulting `BadRequestError` is not awaited, which surfaces as an `unhandledRejection`. With `NODE_ENV=development` the handler re-throws it and the process dies.
5. **C-05 [X-01]: dump history cleanup deletes core files it should keep.** `dumps.slice(0, dumps.length - coredump)` with a negative end removes the oldest dump's core file as soon as there are fewer dumps than `history.coredump`. The code comment claims a non-positive end yields an empty list, which is false.
6. **C-06: the CLI options of `start-kuzzle-server` now take effect (TD-84).** Anyone who passed `--mappings`, `--securities`, `--fixtures`, `--vault-key`, `--secrets-file` or `--enable-plugins` (silently ignored on BASE) now gets imports, a different vault key or file, or a startup crash. The crash hits `--enable-plugins` always in the published image, and any bad path, missing value or numeric vault key. `--help` and `--version` now print and exit 0 instead of starting the server.
7. **C-07: `Kuzzle.id` is now set.** It used to be `undefined` everywhere. The ADR lists three carriers that change. It omits two client-visible ones: every API response body now has a `node` field (BASE left it out), and the `X-Kuzzle-Node` HTTP response header, which was the literal string `"undefined"` on BASE, now carries the node name.
8. **Rolling upgrade from v2.56.0 is wire-compatible.** `sync.proto` is unchanged. `command.proto` only adds two messages under a new command topic. A BASE node answers the unknown `retransmit` topic with `DISCARDED`, and HEAD then treats the gap as it always did (self-eviction, now with exit 1). There are two new strictness checks on incoming notifications (C-13), which v2.56.0 senders satisfy.
9. **Configuration loading accepts and rejects exactly what BASE did, apart from the new `cluster.retransmitBuffer` key.** 22 edge cases were run through both `loadConfig()` builds (see below). No existing configuration is rejected or reinterpreted.

## Configuration loading: what was run

`$S/config-work/load.js <worktree>` calls each side's built `dist/lib/config/index.js` `loadConfig()`. `rc` reads `kuzzle_config=<file>` and `kuzzle_*` environment variables, and no stubs were needed. Results were identical on both sides except where noted:

| case | BASE | HEAD |
|---|---|---|
| defaults | OK | OK (+ `retransmitBuffer`) |
| `kuzzle_limits__concurrentRequests=10`, `limits.concurrentRequests:"10"` in a file | OK → 10 | OK → 10 |
| `limits: null` | `invalid_type` | `invalid_type` |
| `maxFormFileSize: "abc"` / `null` | AssertionError | AssertionError (same text) |
| `websocket.idleTimeout: 0` | OK | OK (only the assertion message text changed, `>= 1000` → `>= 0`) |

Static review agrees: `lib/config/index.ts` only changes the new cluster check, two assertion messages (the websocket `idleTimeout` text; the http `accessControlAllowOriginUseRegExp` message now prints the right value), a `null` guard on `maxFormFileSize` with the same outcome, and `cannot_parse` for a non-Error throw. `unstringify`, the merge order, preprocessing and redis `database` → `options.db` are unchanged. Note that `rc` also folds CLI arguments into the config on both sides, so `--vault-key x` becomes `config["vault-key"]`. This is harmless and unchanged.
