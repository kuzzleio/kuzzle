# A3: client-facing API and plugin event surface, v2.56.0 vs 2-dev `0855cd70f`

BASE = `$S/base` (tag `v2.56.0`), HEAD = `$S/head` (`0855cd70f`). File:line refs point into `lib/` of each worktree. Nearly all of this comes from reading both sides. Three things were executed against the built `dist/` of both worktrees: the route-table dump, the native controller/action dump and the OpenAPI generation. Every row was cross-checked against `docs/adr-001/type-debt-register.md` and `steps/*.md`. The `src` column gives the id from the working notes (`api-work/part-*.md`), so each row can be traced back.

## Summary: top risks first

1. **R-01, multipart `maxFormFileSize` is now enforced (high).** In v2.56.0 the limit was compared against an unset field, so it never applied. Now any part over 1MB (the default) is rejected with `network.http.file_too_large` (413). An install that raised `maxRequestSize` but left `maxFormFileSize` alone will start rejecting uploads it accepted before. This was intended (TD-52, #2769), but it needs a migration note.
2. **R-02, HTTP connections now carry every request header (high, security/logs).** They used to carry `{}` because of a uWS quirk. The headers now show up on `connection:new` / `connection:remove` hook payloads and in `router.connections`. They also go into **logstash access logs**, which serialise the whole `connection`, so those logs now contain cookies, `Authorization` and any custom credential headers. The JWT was already in those logs through `request.input`, but cookies and other headers were not. TD-52 does not mention this side-effect.
3. **R-03, a native controller that crashes reports a different error id (medium).** A non-Kuzzle error thrown by a native controller used to come back as `plugin.runtime.unexpected_error` (PluginImplementationError). It now comes back as `core.fatal.unexpected_error` (InternalError). Status is still 500, but the id, code, name and message all change, both for clients and for the `request:onError` / `<ctrl>:error<Action>` pipes. Intended (TD-21 → TD-27, #2709); already on step 15's known list.
4. **R-04, errors from the WebSocket `afterParsingPayload` pipe are no longer rewrapped (medium).** Before, any error there became `network.websocket.unexpected_error` (400). Now a KuzzleError thrown by a plugin reaches the client with its own id and status. Not recorded anywhere (105806725).
5. **R-05, the `Protocol` base class for custom protocol plugins changed (medium).** `entryPoint` is now a getter-only accessor, so assigning `this.entryPoint` throws. Reading `entryPoint` or `maxRequestSize` before `init()` also throws now. The register records this as typing work, not as a plugin-API change.
6. **R-06, document actions sent with no body return 400 instead of 500 (low-medium).** This covers `deleteFields`, `upsert` and the five `m*` writes. They now fail with `api.assert.body_required` (400) where they used to fail with a TypeError wrapped as a 500. Not recorded (3647a192c).
7. **R-07, the `node` field of realtime notifications is filled in.** It used to be absent because `Kuzzle.id` was never assigned; it now holds the node name. Intended and recorded (step 12, K5).

**No plugin-facing event was removed or renamed.** The sweep found 412 (call, name) pairs on each side, and the templated names match. Payloads are the same at every call site, apart from the error objects in R-03 and R-15.

**No route or action was removed or renamed.** The route table has 298 entries in BASE and 299 in HEAD; the one extra is R-08. All 12 native controllers have identical action sets.
