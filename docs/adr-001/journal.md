**[Step 12 — Sprint 9, the strict flip](steps/12-sprint-9-strict-flip.md) is done and frozen** (2026-09-18 → 2026-09-21; K0 [#2799](https://github.com/kuzzleio/kuzzle/pull/2799), K1 [#2800](https://github.com/kuzzleio/kuzzle/pull/2800), K2 [#2801](https://github.com/kuzzleio/kuzzle/pull/2801), K3 [#2802](https://github.com/kuzzleio/kuzzle/pull/2802), K4+K5 [#2803](https://github.com/kuzzleio/kuzzle/pull/2803), K6 `PR_K6_PLACEHOLDER`). **1 673 strict errors → 0 over four days**, and `strict: true` is in `tsconfig.json`. Axis 3 closes; [TD-54](type-debt-register.md#td-54) closes with it, having become the step rather than remaining a finding. The yield is the part worth remembering: clearing the 95% that was *deferred* rather than blocked surfaced a dozen defects the runtime could reach — two unreachable error codes (`subCode` in both Elasticsearch wrappers, `notconnected` in `redis.ts`), a `Kuzzle.id` declared and never assigned, `auth:logout` clearing its cookie by serialising the string `"null"`, and `promiseAllN([])` answering a non-promise. The step also shipped a boot-breaking regression and caught it in CI: `Redis.setCommands` hoisted an indexed read out of its call site — exactly what `noUncheckedIndexedAccess` asks for — and lost the receiver, so every ioredis command threw. The unit suites were green because they stub the client; all 30 functional shards and both Build-and-Run jobs were not. It is the **second** telling, sprint 5's `funnel.doAction` being the first.

**The flip itself was filed as mechanical and was not, for two reasons neither of which was visible from the step's own numbers.** `strict` is a property of a **program**: the 1 673 were measured through `tsconfig.strict.json` (`lib/` + `index.ts`), while the root `tsconfig.json` also included the specs, where the same flag reports **773** more errors — and `npm run build` is a bare `tsc`, so the flip as filed does not produce a strict repository but one that does not build. The answer is two programs, `tsconfig.json` (production, strict, what `dist/` is emitted from) and `tsconfig.tests.json` (the specs, unchanged checking), and those 773 are step 13's measured starting point. Narrowing the production `include` then dropped 749 emitted files; `check-build-payload.sh` stayed green, because every file `package.json` promises was still there — but `.mocharc` globs `dist/test/**/*.test.js`, so the 148-file Mocha suite had quietly lost its entire input, three config files away from anything the gate reads. `npm run build:tests` puts it back. _A payload gate derived from the package's promises cannot see a consumer that is not a package consumer; running the suites is what saw it._ And emitting the tests after a build surfaced two Mocha specs requiring the repository **as a directory** (`require("../../..")`), which resolves through `package.json` to `dist/index.d.ts` — invisible for as long as `npm run build` started by deleting `dist/`.
